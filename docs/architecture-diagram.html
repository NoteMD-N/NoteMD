01 — Data flow

Everything at rest is in the EU. One hop is not.

The headline for the DPIA: the database, audio storage, authentication and real-time transcription all sit inside the EEA. Transcripts and patient identifiers are sent to OpenAI, which is currently served globally — this is the sole route by which patient data leaves the EEA, and it closes when the EU-resident OpenAI project is enabled.

Inside the EEA
Clinician browser React SPA · served by Render Microphone capture held in memory. Transcript cached locally, namespaced per user, purged at sign-out.
↓
Authentication Supabase Auth · eu-west-1 Email, password hash, JWT session.
Edge functions Supabase Deno · eu-west-1 11 functions. Processing only — nothing persisted here.
↓
Real-time transcription wss://api.eu.deepgram.com · eu-central-1 Consultation audio, streamed direct from browser. No patient identifiers. A — verified 24 Aug
↓
Database Postgres · eu-west-1 Transcripts, letters, patient identifiers. RLS on every table.
Audio storage Supabase Storage · eu-west-1 Private bucket, per-user prefix. Auto-purged after 30 days.
⚠ Transcript + patient identifiers cross the EEA boundary
Outside the EEA
OpenAI api.openai.com · global Dictation audio, transcripts, patient name and NHS number, template prompts. Retained up to 30 days unless Zero Data Retention is enabled. Not used for training. D — EU project + ZDR

05 — Outstanding

What to action, in order

01 OpenAI — Zero Data Retention and an EU-resident project DThe only route by which patient data leaves the EEA, and the only item with external lead time. The application is already built to switch via one environment variable once the account is enabled. Start this first.
02 Per-patient location, export and deletion CCurrent tooling operates per clinician account. A DPIA is likely to require the ability to act on a single patient's records.
03 Resend — confirm and move to the EU region DLetters and transcripts are emailed through it, so it carries patient data.
04 Delete the unused legacy ASR service CStill deployed in Virginia but receives no traffic. Deleting it removes a US processor and the Hugging Face dependency outright.
05 Extend the audit trail CThe table and its append-only guarantees exist; event coverage needs logins, record access and letter generation.
06 Multi-factor authentication and password reset CBoth will be queried for a system holding special category data.
07 Self-host web fonts CRemoves Google as a recipient of clinician IP addresses on every page load.
08 Commission an independent penetration test DStandard before NHS go-live, and expected for DTAC.
09 Confirm regions and backup policy BRender region, Resend region, Supabase backup window, and how long erased data persists in backups.
Prepared by the development team as technical evidence. It records the system as built and is not legal advice — lawful basis, the Article 9 condition and transfer assessments require sign-off by a data protection officer. Until Zero Data Retention is granted, the recommendation is to use synthetic or anonymised data for pilots and demonstrations.
